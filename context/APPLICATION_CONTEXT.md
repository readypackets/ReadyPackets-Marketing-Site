# ReadyPackets Independent Marketing Website — Application Context

## Purpose

This repository is the independent public marketing website for ReadyPackets. It provides anonymous, indexable, accessible information about the ReadyPackets story, process, solution areas, frequently asked questions, contact route, accessibility, privacy/cookie notice, and website terms.

It is deliberately separate from the ReadyPackets portal. The portal holds authentication, customer data, orders, uploads, audio, documents, payments, configuration, and all sensitive application controls.

## Hard boundaries

| Boundary | Marketing website | Portal |
| --- | --- | --- |
| Primary host | `www.readypackets.com` | `my.readypackets.com` / `portal.readypackets.com` |
| Deployment | Static artifact to shared hosting | Hardened self-hosted VPS |
| Runtime | HTML, CSS, vanilla JavaScript only | Node/Express, MySQL, private storage, workers |
| Customer data | None | Authorized portal only |
| Authentication | None | Local auth/MFA and configured enterprise SSO |
| Cookies | Marketing privacy preference only | Host-only secure portal session/CSRF cookies |
| Secrets | None | VPS protected configuration only |
| Cross-origin access | No portal API calls | No marketing-host session sharing |

The static site must never become a proxy for, replica of, or client-side access path to portal data. A link to the portal is not a shared origin or a shared security context.

## Stack and build

- Semantic HTML generated by `scripts/build.mjs`
- Custom responsive CSS in `src/assets/css/site.css`
- Vanilla JavaScript in `src/assets/js/site.js`
- No framework, dependency installation, SSR service, API client, database, server process, or host-specific runtime requirement
- Node.js is used only to build, validate, package, and optionally preview the static output
- Hosted artifact is `dist/`

## Privacy and analytics

Microsoft Clarity and PostHog are optional capability only. Provider configuration is public browser configuration and lives in `src/assets/js/site-config.js`; it must contain only project identifiers—not secrets. Both remain disabled until the visitor gives affirmative Analytics consent. The code disables PostHog autocapture/session replay and sends only reviewed marketing path events.

Any provider enablement requires privacy/legal review, provider-side data-region/retention/masking configuration, and post-deployment testing. No cross-site portal analytics identifier is implemented.

## Accessibility

The implementation target is WCAG 2.2 AA. Test every deployed page with keyboard navigation, screen readers, zoom/reflow, reduced motion, current automated scanners, and real users where possible. Treat feedback as operational work; record and remediate issues promptly.

## Discoverability

The source builds conventional search-engine and answer-engine signals:

- Static readable HTML per page
- Canonical URLs, descriptive metadata, Open Graph/Twitter previews
- Organization/WebSite and FAQ JSON-LD
- `robots.txt`, `sitemap.xml`, `llms.txt`, and `ai.txt`
- Clear professional boundaries and canonical source/citation guidance

These controls improve crawlability and factual retrieval; they do not guarantee ranking, inclusion, or answer-engine representation.

## Hosting

Hostinger, Bluehost, or another static/shared host can serve `dist/`. Keep the portal on the VPS. `.htaccess` provides an Apache/LiteSpeed security baseline; hosts that do not support it must configure equivalent security headers and canonical redirects in the host/CDN layer.

See `docs/HOSTINGER_BLUEHOST_DEPLOYMENT.md` for deployment and rollback steps.

## Operating requirements

- Pin a reviewed Git commit for every release.
- Run `npm run package` before upload.
- Preserve the previous release archive and its commit for rollback.
- Do not deploy secrets, hidden portal configuration, source `.env` files, or portal backups.
- Verify production headers, robots/sitemap, canonical URLs, portal links, consent behavior, accessibility, and no analytics requests before consent.
- Record every material change in `SESSION_LOG.md`.
